## 1. เปิดมอนิเตอร์

```bash
npm run status          # เปิดแบบสด รีเฟรชทุก 15 วินาที
npm run status:once     # เช็ครอบเดียวแล้วออก (เอาไว้เช็คเร็ว ๆ)
npm run status -- 5     # เปลี่ยนความถี่เป็นทุก 5 วินาที
npm run status:old      # เวอร์ชันเก่า (bash) เก็บไว้เผื่อฉุกเฉิน
```

- ออกด้วย `Ctrl+C`
- **ขยายหน้าต่างเทอร์มินัลให้กว้างอย่างน้อย 100 คอลัมน์** ไม่งั้นข้อความท้ายบรรทัดจะถูกตัดด้วย `…`
- ตัวเลขทุกอย่างเป็นข้อมูลสด อ่านจากฐานข้อมูลและโปรเซสจริง ไม่มีการเดา

## 2. ลำดับการอ่าน

**อ่านจากล่างขึ้นบน** — แถบสีล่างสุดตอบคำถามเดียวว่า "ต้องลงมือทำอะไรไหม"

| แถบล่างสุด | แปลว่า | ต้องทำ |
|---|---|---|
| 🟩 เขียว · "ทำงานปกติ — ไม่มีปัญหา" | ทุกบริการขึ้นครบ ไม่มี error สด | ปิดจอได้เลย |
| 🟨 เหลือง · "มีบางอย่างต้องดู" | ยังทำงานได้ แต่มีคำเตือน | ดูเมื่อว่าง ไม่ด่วน |
| 🟥 แดง · "มีปัญหา" | มีบริการล่ม หรือต้องล็อกอินใหม่ | **ต้องแก้** |

เห็นเหลือง/แดงแล้วค่อยไล่หาแถวที่ไม่ใช่ `●` เขียว — แถวเขียวข้ามได้หมด

## 3. สัญลักษณ์และคอลัมน์

### 3.1 สัญลักษณ์สถานะ

| สัญลักษณ์ | คำ | สี | ความหมายจริง |
|---|---|---|---|
| `●` | UP | เขียว | โปรเซสรันอยู่ และไม่มี error สดในล็อก |
| `▲` | WARN | เหลือง | **ยังรันอยู่** แต่พบ error ซ้ำในล็อก 5 นาทีล่าสุด |
| `◆` | AUTH | ม่วง | เซสชัน/กุญแจหมดอายุ ต้องรันคำสั่งล็อกอินใหม่ |
| `✕` | DOWN | แดง | โปรเซสไม่ได้รันเลย |
| `·` | — | เทา | แถวข้อมูลเฉย ๆ ไม่ใช่สถานะขึ้น/ลง |

### 3.2 คอลัมน์ในแถวบริการ

```
● discord   UP    32m       ท่อ Discord (ข้อความ+เสียง) · pid 13672
│ │         │     │         │
│ │         │     │         └─ รายละเอียด: หน้าที่ + pid หรือข้อความ error
│ │         │     └─ uptime: รันมานานแค่ไหนแล้ว
│ │         └─ คำสถานะ
│ └─ ชื่อบริการ
└─ สัญลักษณ์สถานะ
```

**คอลัมน์ uptime สำคัญกว่าที่คิด** — ถ้าตัวเลขนี้**รีเซ็ตเป็น `0m` บ่อย ๆ ทุกครั้งที่รีเฟรช** แปลว่าบริการนั้นล่มแล้ว watchdog ปลุกใหม่วนไม่หยุด ซึ่งอันตรายกว่า `WARN` ที่นิ่ง ๆ เพราะแปลว่ามันพังจริงแต่ซ่อนอยู่

### 3.3 หัวกล่อง

หัวกล่องขวามือสรุปสถานะทั้งโซนให้ในบรรทัดเดียว

- `WAAN · ระบบบริษัท ─── 7 ขึ้นครบ` หรือ `4 ขึ้น · 3 มีปัญหา`
- `VEX · เลขาส่วนตัวของโด้ ─── ไม่อยู่ในสาย · โหมดเรียกชื่อ`

## 4. โซน WAAN · ระบบบริษัท

### 4.1 บริการ 7 ตัว

| ชื่อ | หน้าที่ | ล่มแล้วเกิดอะไร | คำสั่งล็อกอินใหม่ |
|---|---|---|---|
| **web** | Next.js API `:3000` — **สมองกลางของทุกบอท** | **พังหมดทั้งระบบ** ทั้งวานและ Vex | — |
| **bot** | ท่อ Telegram ของน้องวาน | กลุ่มบริษัททักแล้วเงียบ | — |
| **drive** | เฝ้าไฟล์ใหม่ใน Google Drive | ไฟล์เข้าแล้ววานไม่รู้ | `npm run drive:auth` |
| **oho** | เฝ้าแชท OHO | แชทลูกค้าเข้าแล้วไม่แจ้ง | `npm run oho:auth` |
| **fb** | เฝ้ากล่องข้อความ Facebook | ข้อความ FB ไม่เด้ง | `npm run fb:auth` |
| **line** | เฝ้า LINE OA | ข้อความ LINE ไม่เด้ง | `npm run line:auth` |
| **refund** | เฝ้าคำขอคืนเครดิต Thunder | คำขอคืนเงินไม่เด้ง | `npm run thunder:auth` |

> **`web` เป็นรากของทุกอย่าง** — ทุกบริการยิงเข้า API ตัวเดียวกัน ถ้า web ล่ม ตัวอื่นจะขึ้น `fetch failed` ตามกันหมด นั่นคือ**อาการต่อเนื่อง ไม่ใช่ปัญหาของตัวมันเอง**

### 4.2 คลังกลาง

ไม่ใช่โปรเซส แต่เป็นสภาพของข้อมูลและกุญแจ

| แถว | ความหมาย | ต้องระวังอะไร |
|---|---|---|
| **gtoken** | กุญแจ Google (Drive + Calendar) | ข้อความ "access หมดแล้ว (ต่อเอง)" = **ปกติ** มันต่ออายุเองทุกครั้งที่ใช้ · ถ้าขึ้น "ไม่มี .drive-token.json" ถึงจะต้องรัน `npm run drive:auth` |
| **ollama** | เครื่องแปลงข้อความเป็นเวกเตอร์ (bge-m3) รันในเครื่อง | ถ้าไม่พร้อม การค้นแบบเข้าใจความหมายจะปิด ระบบอื่นยังทำงานปกติ |
| **brain** | ความจำลูกค้า: จำนวนลูกค้า · ข้อเท็จจริง · Q&A ในคลัง | เป็นสถิติ ไม่ต้องแก้ |
| **chat** | รายงานแชท: บทสนทนาที่เก็บ · วิเคราะห์ไปแล้วกี่อัน · รายงานกี่วัน | ถ้า "วิเคราะห์แล้ว" ห่างจาก "บทสนทนา" มาก แปลว่าคิววิเคราะห์ค้าง |

## 5. โซน VEX · เลขาส่วนตัว

### 5.1 บริการ 4 ตัว

| ชื่อ | หน้าที่ | ล่มแล้วเกิดอะไร |
|---|---|---|
| **kiki** | ท่อ Telegram ของ Vex (`@kiki_lekha_bot`) | ทักใน Telegram แล้วเงียบ |
| **discord** | ท่อ Discord ทั้งข้อความและเสียง | Vex ออฟไลน์ใน Discord ไม่พูด ไม่ตอบ ไม่เข้าห้องเสียง |
| **eyes** | **ตา** — เฝ้าข้อความขาเข้า แล้วให้คะแนนว่าควรพูดขึ้นมาไหม | Vex เงียบสนิท ไม่รู้ว่ามีอะไรเข้ามาเลย |
| **chrome** | Chrome ตัวจริงพอร์ต `9222` | สั่งให้เปิดเว็บ / กดหน้าจอ / ดึงข้อมูลจากเว็บไม่ได้ |

> **`chrome` เช็คต่างจากตัวอื่น** — launchd ตั้งเป็นแบบยิงครั้งเดียวจบ (`KeepAlive false`) เช็ค pid ไม่ได้ มอนิเตอร์เลยเคาะพอร์ตดีบัก `9222` แทน

### 5.2 สถานะสด — แถบวัด

**หลักการอ่าน: แถบยิ่งยาว = ยิ่งบวม = ยิ่งต้องระบาย**

| แถว | นับอะไร | ยาวแปลว่า | ควรอยู่ที่ | วิธีระบาย |
|---|---|---|---|---|
| **คิวพูด** | เรื่องที่ Vex อยากพูดแต่ยังไม่ได้พูด | คุณไม่อยู่ในสาย มันเลยกองไว้ (ตามดีไซน์ ห้ามพูดใส่ห้องว่าง) | 0-2 | เข้าห้องเสียง `สาย` แล้วถาม "มีอะไรบ้าง" |
| **กองรอเล่า** | เรื่องที่ตัวให้คะแนนตัดสินว่า "ไม่ด่วน เก็บไว้เล่าทีหลัง" | สะสมมานานยังไม่ระบาย | 0-5 | เหมือนข้างบน |
| **เรื่องค้าง** | บทสนทนาที่ยังไม่จบ (focus stack) | มีหลายเรื่องคาอยู่พร้อมกัน | 0-5 | หายเองเมื่อคุยเรื่องนั้นจบ |
| **งานค้าง** | งานในกระดานที่ยังไม่ปิด | มีงานค้างจริง | ตามจริง | สั่ง "งานที่ค้างมีอะไรบ้าง" |
| **รอระบุเงิน** | รายการเงินที่ยังไม่รู้ว่าค่าอะไร | ต้องไปตอบให้มันรู้ | 0-5 | สั่ง "ขอลิสต์รายการรอระบุ" ตอบเป็นชุดทีเดียว |
| **งานเบื้องหลัง** | งาน Hermes ที่กำลังรันตอนนี้ | รันพร้อมกันหลายงาน | 0-2 | รอให้เสร็จ หรือสั่งยกเลิก |

ข้อความท้ายแถบคือตัวอย่างล่าสุดของกองนั้น เช่น กองรอเล่าจะโชว์หัวเรื่องล่าสุดที่มันเก็บไว้

**เลขเปลี่ยนสีเหลือง** เมื่อเกินเกณฑ์: คิวพูดมีรายการค้างลองซ้ำ · กองรอเล่า ≥ 10 · งานครบกำหนดวันนี้ · รอระบุเงิน ≥ 10 · Hermes ล้มเหลว

### 5.3 รอโด้ตัดสินใจ

**โซนนี้โผล่เฉพาะตอนมีเรื่องรอคุณกด — ไม่มีเรื่อง = ไม่โผล่ ไม่รกจอ**

| ข้อความที่เจอ | แปลว่า | ทำยังไง |
|---|---|---|
| `ร่างถึง <ชื่อ> รอยืนยัน` | Vex เตรียมข้อความจะส่งหาคนนั้นแล้ว รอคุณอนุมัติ | ตอบ "ส่งเลย" / "แก้เป็น..." / "ไม่ต้อง" |
| `ร่างถึง <ชื่อ> รอยืนยัน · (ยังไม่มีเนื้อความ)` | ร่างค้างจากการทดสอบ ไม่มีเนื้อความจริง | ล้างทิ้งด้วยคำสั่งด้านล่าง |
| `กุญแจขาด: <คำสั่ง>` | มีกุญแจ/เซสชันหาย | รันคำสั่งที่มันบอก |
| `โควตาตัน: <ชื่อ>` | โควตา API ของบริการนั้นเต็มภายใน 6 ชม.ที่ผ่านมา | รอรีเซ็ต หรือเปลี่ยนโมเดล |

**ล้างร่างค้าง:**
```bash

```

## 8. คู่มือแก้ปัญหา

### กฎเหล็กข้อเดียว

> **ถ้า `web` แดง ให้แก้ `web` ก่อนอย่างอื่นเสมอ**
>
> ทุกอย่างวิ่งผ่าน API ตัวเดียวกัน พอ web ล่ม `drive` `refund` `eyes` `discord` จะขึ้น `fetch failed` ตามกันหมด
> **นั่นไม่ใช่ปัญหาของมัน** พอ web กลับมา ส่วนใหญ่หายเอง อย่าไปไล่รีสตาร์ททีละตัวให้เสียเวลา

### ตารางอาการ → สาเหตุ → วิธีแก้

| อาการ | สาเหตุที่พบบ่อยที่สุด | แก้ยังไง |
|---|---|---|
| `web DOWN` แต่แป๊บเดียวหายเอง | **Next.js กำลัง recompile ตอนมีคนแก้โค้ด** — เจอบ่อยมากเวลาพัฒนาอยู่ | **ไม่ต้องทำอะไร** รอ 10-30 วินาที |
| `web DOWN` ค้างเกิน 2 นาที | เซิร์ฟเวอร์ตายจริง | `launchctl kickstart -k gui/$(id -u)/com.changoh.web` |
| แถวไหนก็ตาม `✕ DOWN` | โปรเซสไม่ได้รัน | `launchctl kickstart -k gui/$(id -u)/com.changoh.<label>` |
| `◆ AUTH` | เซสชันหมดอายุ | รันคำสั่งที่แสดงในบรรทัดนั้นเลย |
| `▲ WARN` + `fetch failed` | ต่อ API ไม่ได้ | เช็ค `web` ก่อน · ถ้า web ปกติค่อยดูล็อกตัวนั้น |
| `▲ WARN` + `บั๊กโค้ด` | โค้ดพังจริง | `tail -40 .run-logs/<ชื่อ>.log` แล้วส่งให้ดู |
| `▲ WARN` + `เซสชันน่าจะหมดอายุ` | ต้องล็อกอินใหม่ | รันคำสั่ง auth ที่บอกในบรรทัด |
| `chrome WARN` | Chrome ตัวจริงไม่เปิด | `npm run kiki:chrome` |
| uptime รีเซ็ตเป็น `0m` วนไม่หยุด | ล่มแล้วถูกปลุกวน — มีปัญหาจริงซ่อนอยู่ | **อย่าปลุกซ้ำเฉย ๆ** ดูล็อกหาสาเหตุก่อน |
| ทุกอย่างล่มพร้อมกัน | Mac หลับ หรือล็อกเอาต์ | `npm run watchdog` |
| `ollama` ไม่พร้อม | Ollama ไม่ได้รัน | เปิดแอป Ollama หรือ `ollama serve` |
| `vector` น้อยกว่าจำนวนโน้ตมาก | index ไม่ครบ | สั่ง Vex ว่า "รีอินเด็กซ์คลังส่วนตัว" |
| `กุญแจ` ขึ้น "ขาด" | ค่าใน `.env` หาย หรือไฟล์ session หาย | ดูตารางในข้อ 9 |

### ลำดับการตรวจเมื่อ Vex ไม่ตอบเลย

1. `web` ขึ้นไหม → ถ้าไม่ ปลุก web ก่อน
2. `discord` / `kiki` ขึ้นไหม → ถ้าไม่ ปลุกตัวนั้น
3. `eyes` ขึ้นไหม → ถ้าไม่ Vex จะไม่รู้ว่ามีข้อความเข้ามา
4. `กุญแจ` ครบไหม → Discord token / Gemini key หายไหม
5. ยังไม่ได้ → `tail -40 .run-logs/vex-discord.log`

## 10. คำถามที่เจอบ่อย

**ถาม: `web` เด้ง DOWN แล้วหายเองบ่อยมาก ปกติไหม**
ปกติมากตอนกำลังพัฒนา — Next.js dev server จะ recompile ทุกครั้งที่มีคนแก้ไฟล์ ระหว่างนั้นมันไม่ตอบ curl ภายใน 6 วินาที มอนิเตอร์เลยขึ้น DOWN ถ้าหายเองภายในไม่กี่วินาที ไม่ต้องทำอะไร

**ถาม: `gtoken` ขึ้น "access หมดแล้ว (ต่อเอง)" ต้องล็อกอินใหม่ไหม**
ไม่ต้อง — access token ของ Google อายุสั้นมาก (1 ชม.) และระบบต่ออายุเองอัตโนมัติจาก refresh token ที่จะขึ้นว่า "refresh_token ปกติ" ตราบใดที่บรรทัดนั้นยังอยู่ก็ปลอดภัย

**ถาม: ทำไม `คิวพูด` กับ `กองรอเล่า` ถึงบวมทั้งที่ไม่มีอะไรพัง**
เพราะคุณไม่ได้อยู่ในห้องเสียง Vex ถูกออกแบบให้**ห้ามพูดใส่ห้องว่าง** มันจึงกองเรื่องไว้แล้วรอเล่าตอนคุณกลับมา เป็นพฤติกรรมที่ถูกต้อง ไม่ใช่บั๊ก

**ถาม: `▲ WARN` หลายตัวพร้อมกัน ต้องแก้ทีละตัวไหม**
ดู `web` ก่อนเสมอ — ถ้า web เพิ่งล่ม ตัวอื่นจะเตือนตามกันหมดเพราะยิง API ไม่ได้ พอ web กลับมา ล็อกจะหยุด error แล้วมอนิเตอร์จะเคลียร์เองภายใน 5 นาที (หน้าต่างตรวจ error สด)

**ถาม: uptime ของ `bot` เป็น `7m` ทั้งที่ไม่ได้รีสตาร์ทเอง**
watchdog ปลุกให้เพราะมันล่มไป ถ้าเห็นเลขนี้รีเซ็ตบ่อย ๆ ให้ดูล็อกหาสาเหตุที่แท้จริง อย่าปล่อยให้ปลุกวน

**ถาม: ข้อความท้ายบรรทัดโดนตัดด้วย `…` อ่านไม่จบ**
ขยายหน้าต่างเทอร์มินัลให้กว้างขึ้น — มอนิเตอร์ปรับความกว้างตามจอ สูงสุด 96 คอลัมน์ หรือดูรายละเอียดเต็มจากไฟล์ล็อกโดยตรง

**ถาม: อยากดูข้อมูล Vex อย่างเดียว ไม่เอาของบริษัท**
```bash
node scripts/status-vex.mjs
```
จะได้ข้อความล้วนบรรทัดละหัวข้อ เอาไปต่อท่ออื่นได้

## 11. เบื้องหลัง

### 11.1 ไฟล์ที่เกี่ยวข้อง

| ไฟล์ | หน้าที่ |
|---|---|
| `scripts/status.mjs` | ตัวหลัก — เก็บข้อมูลระบบ + วาดกล่อง + ลูปรีเฟรช |
| `scripts/status-vex.mjs` | เก็บข้อมูลฝั่ง Vex จากฐานข้อมูล (ใช้ได้ทั้ง import และรันเดี่ยว) |
| `scripts/usage-cli.mjs` | ข้อมูลโทเค็น/ค่าใช้จ่าย AI |
| `scripts/status.sh` | เวอร์ชันเก่า (bash) เก็บไว้เผื่อฉุกเฉิน |

### 11.2 แหล่งข้อมูลของแต่ละส่วน

| ส่วน | อ่านจาก |
|---|---|
| สถานะบริการขึ้น/ลง | `launchctl list` |
| uptime | `ps -Ao etime=,command=` |
| WARN / AUTH | ไฟล์ใน `.run-logs/*.log` — ดูเฉพาะบรรทัดหลังข้อความ "พร้อมทำงาน" ล่าสุด และเฉพาะล็อกที่เขียนภายใน 5 นาที |
| web | `curl http://localhost:3000` |
| chrome | `curl http://localhost:9222/json/version` |
| ollama | `curl http://localhost:11434/api/tags` |
| ข้อมูล Vex ทั้งหมด | `prisma/changoh.db` (อ่านอย่างเดียว) |
| vector | `prisma/thunder-vec.db` ตาราง `kiki_vec_rowids` |
| โน้ต Obsidian | เดินโฟลเดอร์ `$OBSIDIAN_VAULT_PATH/AI-Personal` นับไฟล์ `.md` |

### 11.3 เกณฑ์ตัดสิน WARN

มอนิเตอร์แยกความรุนแรงของ error 3 ระดับ

| ประเภท | ตัวอย่าง | เกณฑ์ขึ้นเตือน |
|---|---|---|
| **AUTH** | `invalid_grant`, `401`, `เซสชันหมด` | เจอครั้งเดียวก็เตือน |
| **บั๊กโค้ด** | `TypeError`, `MODULE_NOT_FOUND`, `EADDRINUSE` | เจอครั้งเดียวก็เตือน |
| **สะดุดชั่วคราว** | `fetch failed`, `ECONNREFUSED`, `ETIMEDOUT` | ต้องเจอ **≥ 3 ครั้ง** ถึงเตือน (1-2 ครั้งถือว่าปกติ ต่อกลับเองได้) |

### 11.4 ทำไมเขียนด้วย Node ไม่ใช่ bash

กรอบกล่องต้องรู้ "ความกว้างที่แสดงจริง" ของข้อความ แต่

- ภาษาไทยมีสระบน/ล่างและวรรณยุกต์ (ั ิ ี ึ ื ุ ู ่ ้ ๊ ๋ ์) ที่กิน **0 คอลัมน์**
- อิโมจิและอักษรจีน/ญี่ปุ่นกิน **2 คอลัมน์**

bash นับได้แค่ไบต์หรือจำนวนตัวอักษร → ขอบกล่องขวาจะเบี้ยวทุกบรรทัดที่มีภาษาไทย
`status.mjs` จึงมีฟังก์ชันวัดความกว้างจริงเอง (`dw()`) ทำให้ทุกบรรทัดในกล่องกว้างเท่ากันเป๊ะ

ผลพลอยได้: เร็วขึ้นด้วย เพราะเรียก `ps` และ `launchctl` รอบเดียวต่อการรีเฟรช (เวอร์ชัน bash เรียก `ps` ใหม่ทุกบริการ)

## 12. อภิธานศัพท์

| คำ | ความหมาย |
|---|---|
| **launchd / launchctl** | ระบบจัดการโปรเซสของ macOS ที่เปิดบริการให้อัตโนมัติตอนล็อกอิน |
| **watchdog** | ตัวเฝ้าที่ปลุกบริการที่ล่มให้ขึ้นมาใหม่ |
| **ingest** | API กลางที่รับข้อความเข้าแล้วให้สมองของ Vex ตัดสินใจ (`/api/kiki/ingest`) |
| **ตา (eyes)** | ตัวเฝ้าข้อความขาเข้าจาก Telegram/Gmail แล้วให้คะแนนว่าควรพูดขึ้นมาไหม |
| **คิวพูด (VexOutbox)** | คิวข้อความที่รอส่งเข้าห้องเสียง/ห้องข้อความ Discord |
| **กองรอเล่า (interrupt pile)** | เรื่องที่ตัวให้คะแนนตัดสินว่าไม่ด่วน เก็บไว้เล่ารวบทีหลัง |
| **เรื่องค้าง (focus stack)** | บทสนทนาที่ยังไม่จบ — ใช้ตอบว่า "อันนั้น" หมายถึงเรื่องไหน |
| **Hermes** | ผู้ช่วยเบื้องหลังที่รับงานยาวไปทำแยกโปรเซส แล้วส่งผลกลับมาทีหลัง |
| **โหมดเรียกชื่อ** | Vex หลับอยู่ ตื่นเมื่อได้ยินคำว่า "Vex" |
| **vector index** | ดัชนีความหมายของโน้ต ใช้ค้นแบบเข้าใจความหมาย ไม่ใช่แค่ตรงคำ |
| **AI-Personal** | โฟลเดอร์ใน Obsidian ที่ Vex เขียนได้ที่เดียว (แยกขาดจากคลังบริษัท) |
