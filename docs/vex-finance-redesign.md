## ส่วนที่ 2 — ทำไมโครงเดิมทำสิ่งที่โด้ขอไม่ได้

โด้ขอ 6 อย่าง — เช็คกับโครงเดิมทีละข้อ

| สิ่งที่ขอ | โครงเดิมทำได้ไหม | ติดตรงไหน |
|---|---|---|
| เดือนนี้จ่ายค่าหนี้อะไรไปแล้วบ้าง | ❌ | ไม่มีประวัติการจ่าย — `Debt.amount` ถูกเขียนทับ ของเก่าหายทันที |
| เหลือเท่าไหร่ กี่ % | 🟡 | คำนวณได้ แต่ไม่มี "ยอดตั้งต้น" เลยไม่รู้ว่าปลดไปกี่ % แล้ว |
| หนี้เป็นกี่ % ของทั้งหมด | 🟡 | คำนวณสดได้ แต่ไม่มีการ์ดไหนแสดง |
| เตือนจ่ายบัตร | 🟡 | มี `remindedInstallmentYm` แต่วันครบกำหนดในระบบเป็น "วันที่ 1" ทุกใบ ซึ่งไม่จริง |
| แยกภาพแบบการ์ด | ❌ | มี `financeCardHtml` (รายรับ-จ่าย) กับ `healthCardHtml` (ภาพรวม) — ไม่มีการ์ดหนี้เลย |
| วิเคราะห์จากข้อมูลจริง | 🟡 | `analyzeFinance()` มี แต่อิง `FinanceTxn` ซึ่งตอนนี้ = 0 |

### ช่องโหว่ระดับโครงสร้าง 6 ข้อ

1. **`Debt` มีช่องเดียวคือ "ยอดคงเหลือ"** — แยกไม่ออกระหว่างบัตรหมุนเวียน (มีวงเงิน ใช้ซ้ำได้ ดอกทบ) กับสินเชื่อผ่อนปิด (งวดคงที่ จบแล้วจบเลย) ทั้งที่พฤติกรรมคนละเรื่องกันสิ้นเชิง
2. **ไม่มีวงเงิน** → คำนวณ utilization ไม่ได้ ทั้งที่เป็นตัวเลขที่แดงที่สุดในชุดนี้ (90.5%)
3. **ไม่มีอัตราดอกเบี้ย** → ตอบไม่ได้ว่า "จ่ายขั้นต่ำไปเรื่อย ๆ อีกกี่ปีถึงหมด" ซึ่งเป็นคำถามที่เปลี่ยนการตัดสินใจมากที่สุด
4. **ไม่มีประวัติการจ่าย** → "จ่ายไปแล้วเท่าไหร่" ตอบไม่ได้เลย และไม่มีทางรู้ว่าเดือนไหนจ่ายช้า
5. **ไม่มีจำนวนงวด** → จอคอม "3 จาก 9 งวด" เก็บไม่ได้ ทั้งที่โด้เขียนมาให้ชัด ๆ
6. **`applyBaseline` ทิ้งข้อมูลเงียบ** → บั๊กที่ทำให้วันนี้หายไป 3 ก้อน

## ส่วนที่ 3 — ระบบใหม่ที่เสนอ

### A. ยกเครื่องโครงข้อมูลหนี้ (`Debt` เพิ่มฟิลด์)

| ฟิลด์ใหม่ | ไว้ทำอะไร |
|---|---|
| `kind` | `revolving` (บัตร) · `installment` (ผ่อนปิด) · `personal` (ยืมคน) — คำนวณคนละสูตร |
| `creditLimit` / `availableCredit` | วงเงิน + คงเหลือ → utilization รายใบและรวม |
| `interestRate` | ดอก %/ปี → พยากรณ์ "จ่ายขั้นต่ำอีกกี่เดือนหมด" |
| `termsTotal` / `termsPaid` | จอคอม 9 งวด จ่ายแล้ว 3 → เหลือ 6 |
| `openingAmount` | ยอดตั้งต้นตอนเริ่มติดตาม → โชว์ % ที่ปลดไปแล้ว |
| `dueDay` | วันครบกำหนดจริงของแต่ละใบ (ตอนนี้เป็น 1 หมด ซึ่งไม่จริง) |

**ไม่ทิ้งของเดิม** — `amount` / `installmentAmount` / `installmentDay` ใช้ต่อได้เหมือนเดิม ของใหม่เป็นส่วนขยาย

### B. ตาราง `DebtPayment` ใหม่ — หัวใจของ "จ่ายไปแล้วเท่าไหร่"

```
DebtPayment: debtId · ym (2026-08) · dueDay · amountDue · amountPaid
             paidAt · status (pending | paid | late | skipped) · note
```

- ทุกวันที่ 1 ระบบสร้างแถวรอบเดือนให้ทุกหนี้อัตโนมัติ
- จ่ายแล้ว → บันทึกลงตารางนี้ **แล้วค่อยลด `Debt.amount`** (ไม่ใช่ทับค่าทิ้งแบบเดิม)
- ได้ประวัติย้อนหลังฟรี: เดือนไหนจ่ายช้า จ่ายเกินขั้นต่ำเท่าไหร่ ปลดหนี้เร็วขึ้นกี่เดือน

นี่คือตารางที่ทำให้คำถามของโด้ทุกข้อตอบได้ ถ้าไม่มีตัวนี้ ที่เหลือทำไม่ได้เลย

1. `applyBaseline` เจอรายการข้อมูลไม่ครบ → **ยังลงให้ แล้วรายงานว่าขาดอะไร** ไม่ทิ้งเงียบอีก
2. **ตัวกระทบยอด** — ผลรวมงวดในระบบ vs ที่โด้บอกมา ต่างกันเกิน 1% = ทักทันที
   (ถ้ามีตัวนี้ตั้งแต่แรก บั๊กวันนี้จะถูกจับได้ในวินาทีที่เกิด แทนที่จะรอผมมาไล่ดู DB)
3. `RecurringBill` รับช่วงตัวเลขได้ (`amountMin` / `amountMax`) — ค่าเน็ต 700–1,000 เก็บได้ตรงตามจริง
4. รายรับเก็บ 2 ชั้น: การันตี 38,000 / รวมผันแปร 40,650 — วิเคราะห์ความเสี่ยงใช้ชั้นการันตีเสมอ

## ส่วนที่ 4 — โครงสร้างเงินใหม่ (ข้อเสนอเชิงกลยุทธ์)

### หลักการเดียวที่ทุกอย่างวางอยู่บนนี้

> **ใช้ชีวิตบนรายได้ Thunder อย่างเดียว (22,650) · รายได้งานนอก 18,000 ห้ามแตะ ไปโปะหนี้กับกันชนเท่านั้น**

ตอนนี้ยังมีข้อได้เปรียบที่ไม่ค่อยมีใครมี — **ไม่มีค่าเช่าบ้าน (บริษัทออก) + มีค่าอาหารกลางวัน**
สองอย่างนี้คือเหตุผลเดียวที่ทำให้แผนนี้เป็นไปได้จริง และมันผูกกับการอยู่ Thunder

### ลำดับปลดหนี้ — ผมเสนอแบบผสม ไม่ใช่ตำราล้วน

**เดือนที่ 1 — ปิด Ascend Pay Next (2,365.46) ทิ้งเลย**
เหลือน้อยที่สุด · ปิดได้ในเดือนเดียว · ปลดภาระ 680.13/เดือนทันที
และที่สำคัญกว่า: **ได้วงเงิน 3,000 คืนมาเป็นกันชนฉุกเฉิน** ตอนนี้ทั้งระบบเหลือวงเงินหมุนแค่ 7,378

**เดือนที่ 2–5 — โปะไล่ตามดอกเบี้ยสูงสุด**
ต้องรู้อัตราดอกจริงก่อนถึงจะจัดลำดับได้ (ดูส่วนที่ 5) แต่ถ้าเป็นอัตราตลาดปกติ ลำดับน่าจะเป็น
Umay+ (สินเชื่อบุคคล ดอกแพงสุด) → Ascend Extra → First Choice

**ประมาณการ:** โปะเดือนละ 15,000 + งวดขั้นต่ำเดิม → **บัตรทั้ง 4 ใบหมดใน 4–5 เดือน**
หลังจากนั้นภาระต่อเดือนลดจาก 13,770 → **8,797** (เหลือแค่รถ + มอไซค์ + จอคอม)
= มีเงินเหลือเพิ่มเดือนละ 4,973 ตลอดไป

**สิ่งที่ห้ามทำเด็ดขาดระหว่างนี้:** รูดบัตรใบที่เพิ่งปิด แล้ววนกลับมาที่เดิม
ระบบจะเฝ้าให้ — วงเงินที่ใช้ไปขยับขึ้นเมื่อไหร่ Vex ทัก
