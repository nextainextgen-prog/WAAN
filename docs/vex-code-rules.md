# กติกาโค้ดของ Vex (ห้ามฝืน)

เจ้าของสั่งไว้ 4 ส.ค. 2026: **"ปรับให้ยืดหยุ่น ไม่ต้องฟิกข้อมูลอะไรเลย ปล่อยให้อิสระเหมือน AI ทั่วไป เพียงแต่เป็นเลขาผม"**
และหลังเจอบั๊กซ้ำ: **"ถ้ามีอะไรที่ตั้งฟิกไม่เอา และอย่าให้เกิดเหตุการณ์นี้ขึ้นอีก"**

## 1. ห้ามตัดสินใจด้วย regex

เส้นทางคำสั่งทั้งหมดผ่าน `kiki-router.ts` (อ่านเจตนาด้วยโมเดล) เท่านั้น
regex เหลือได้เฉพาะกรณีที่ชัด 100% และไม่มีทางกำกวม: ปุ่ม callback · คำยืนยัน · การดึงตัวเลข/พารามิเตอร์จากข้อความที่ตรงรูปแบบอยู่แล้ว

เพิ่มความสามารถใหม่ = เพิ่ม entry ใน `INTENT_CATALOG` ที่เดียว (router + รายการความสามารถใน persona อ่านจากตารางนี้ทั้งคู่ ไม่มีทางหลุด sync)

**เคสจริงที่พัง:** "คิดชื่อกลุ่มให้หน่อย อยากได้ประมาณว่า…" → ชนคำว่า "อยากได้" ใน `WISH_RE` → ตอบกลับว่า "อยากได้อะไร ราคาเท่าไหร่"

## 2. ห้ามข้อความสำเร็จรูป

ทุกข้อความที่ส่งหาเจ้าของต้องผ่านตัวใดตัวหนึ่ง:

| ใช้เมื่อ | ตัวช่วย |
| --- | --- |
| ตอบคำถาม / คุย / วิเคราะห์ | `askKiki()` |
| ยืนยันการกระทำ · ทางตัน · ข้อผิดพลาด | `vexLine()` — ใจความเดิม ตัวเลขเดิม แต่คำพูดใหม่ทุกครั้ง |
| แต่งคำพูดจากข้อเท็จจริงที่ระบบคำนวณ | `vexSay()` |
| ลิสต์/ตาราง/รายงานที่ต้องเป็นระเบียบ | `vexList()` / `vexSections()` ใน `kiki-format.ts` |

ยกเว้นได้เมื่อจำเป็นจริง (โควตข้อความที่จะส่งจริง · ลิสต์ข้อมูลดิบ · ตัวดักพังชั้นสุดท้าย) โดยเติมคอมเมนต์ `// canned-ok: <เหตุผล>` ไว้บรรทัดเดียวกันหรือบรรทัดบน

ตรวจด้วย `npm run kiki:check` — ต้องผ่านก่อน commit ทุกครั้ง

**เคสจริงที่พัง:** ถาม "รู้จักประวัติผมมั้ย" 3 แบบ ได้ลิสต์ความจำ 13 ข้อเหมือนกันเป๊ะทั้ง 3 ครั้ง แถมเอา "กฎของ Vex" มาปนกับประวัติเจ้าของ

## 3. ห้ามให้โมเดลเป็นคนยืนยันว่าทำสำเร็จ

การกระทำจริง (ส่งข้อความ · แคปจอ · โพสต์ · บันทึกเงิน) ให้ระบบตรวจหลักฐานเองแล้วรายงาน
เช่น มีไฟล์ภาพจริงถึงบอกว่าแคปแล้ว · เจอตัวชี้ว่าล็อกอินจริงถึงยอมพิมพ์ลงช่องโซเชียล

## 4. เก็บข้อมูลเฉพาะที่เจ้าของสั่ง

ลิงก์ · รูป · วิดีโอ · ไฟล์ = อ่านให้/ตอบให้ได้เสมอ แต่เขียนลงคลัง (Obsidian/`KikiMedia`) เฉพาะเมื่อสั่งให้เก็บ

## 5. ข้อความเข้าแชทต้องอ่านง่าย

ลิสต์ = บรรทัดละรายการเสมอ ห้ามคั่นด้วย `·` ต่อกันเป็นพืด · ซอยบับเบิลได้สูงสุด 3 ก้อน (แยกตามย่อหน้าจริงเท่านั้น)
