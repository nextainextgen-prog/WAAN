# นับโทเค็น Gemini เข้ามอนิเตอร์

> **สถานะ: เสร็จแล้ว 5 ส.ค. 2569 — ต่อครบทั้ง 11 จุด ทดสอบผ่านแล้ว**
> เอกสารนี้เก็บไว้เป็นบันทึกว่าทำอะไรไป และเป็นกติกาสำหรับจุดเรียก Gemini ที่จะเพิ่มในอนาคต
>
> **กฎสำหรับโค้ดใหม่: ห้ามเรียก `fetch` ไปที่ Gemini ตรง ๆ อีก ให้ใช้ `geminiFetch` เสมอ**
> ไม่งั้นโทเค็นก้อนนั้นจะหายจากมอนิเตอร์โดยไม่มีใครรู้

## 1. ทำไมต้องทำ

| | Claude / Codex | Gemini |
|---|---|---|
| ทำงานที่ไหน | CLI ในเครื่อง | API บนคลาวด์ |
| ทิ้งร่องรอยไหม | เขียน `.jsonl` ทุก session | **ไม่เขียนอะไรเลย** |
| อ่านย้อนหลังได้ไหม | ได้ตลอด | **ไม่ได้ — ไม่จดตอนเรียก = หายถาวร** |
| เรื่องเงิน | ค่าสมาชิกรายเดือน ($ ในจอเป็นมูลค่าเทียบเคียง) | **คิดตามโทเค็นจริง = เงินที่จ่ายจริง** |

ตอนนี้ Vex เรียก Gemini 11 จุด ทุกครั้งที่ตอบกลับมามี `usageMetadata` ติดมาด้วย (บอก input/output/total token ครบ) **แต่โยนทิ้งหมด**

สิ่งเดียวที่เก็บอยู่คือ `vex_tts_calls` ซึ่งนับแค่จำนวนครั้งของ TTS ไม่ใช่โทเค็น

และเฟสเสียงกำลังจะเพิ่มจุดเรียกอีก — ถ้าไม่รวมท่อตอนนี้ ทีหลังจะต้องไล่แก้ 20 จุดแทน 11 จุด

## 3. งานที่ต้องทำ — เปลี่ยน 11 จุด

### รูปแบบการแก้

```ts
// ก่อน
const res = await fetch(url, { method: "POST", headers: {...}, body: ... });

// หลัง
const res = await geminiFetch(url, { method: "POST", headers: {...}, body: ... }, "say");
```

**คืน `Response` หน้าตาเดิมเป๊ะ** — บรรทัดถัดไป (`await res.json()`, `res.ok`, `res.status`) ไม่ต้องแก้อะไรเลย

เพิ่ม import ที่หัวไฟล์:
```ts
import { geminiFetch } from "./gemini-usage";
```

## 4. ตั้งเรตราคา (ทำทีหลังก็ได้)

ถ้าไม่ตั้ง มอนิเตอร์จะโชว์**โทเค็นกับจำนวนครั้ง** (ซึ่งเป็นค่าที่วัดมาจริง) แต่ไม่โชว์เงิน

**อย่าเดาราคาใส่เอง** — เช็คราคาจริงจากเอกสารทางการก่อน (ราคาต่างกันตามรุ่น และเปลี่ยนบ่อย)
แล้วใส่ใน `.env`:

```
GEMINI_RATE_IN=<ดอลลาร์ต่อ 1 ล้าน input token>
GEMINI_RATE_OUT=<ดอลลาร์ต่อ 1 ล้าน output token>
USD_THB=36        # ใส่แล้วจะแปลงเป็นบาทให้ · ไม่ใส่ = โชว์เป็นดอลลาร์
```

> ข้อจำกัดที่รู้ตัว: ตอนนี้คิดเรตเดียวกับทุกรุ่น ถ้าอยากแยกเรตต่อรุ่น (flash / pro / tts คนละราคา)
> ต้องขยาย `costOf()` ใน `scripts/usage-gemini.mjs` ให้รับตารางเรตต่อรุ่น

## 5. เทสต์ว่าทำงานจริง

```bash
# 1) แก้จุดเรียกอย่างน้อย 1 จุด แล้วรีสตาร์ท web
launchctl kickstart -k gui/$(id -u)/com.changoh.web

# 2) ทักหา Vex สักข้อความ (เพื่อให้มีการเรียก Gemini จริง)

# 3) รอ ~10 วินาที (ตัวจดรวมยอดในหน่วยความจำก่อนเขียน) แล้วเช็ค
node scripts/usage-gemini.mjs

# ควรได้ประมาณนี้ ไม่ใช่ "ยังไม่มีข้อมูล"
# Gemini  Today       12.4k tok   (in 9k · out 3k)
#         รุ่น         2.5-flash 12.4k
#         เรียก        3 ครั้ง (say 2 · router 1)
#         เดือนนี้      12.4k tok · 3 ครั้ง · ยังไม่ได้ตั้งเรตราคา

node scripts/usage-gemini.mjs --json
```

## 6. หมายเหตุเชิงเทคนิค

**ทำไมต้องอ่าน body แล้วสร้าง `Response` ใหม่**
`Response.body` อ่านได้ครั้งเดียว ถ้าตัวห่ออ่านไปดู `usageMetadata` แล้ว ผู้เรียกจะ `.json()` ไม่ได้อีก
ตัวห่อจึงอ่านเป็น text ครั้งเดียว จดยอด แล้วประกอบ `Response` ใหม่คืนไป (ทุกคำสั่งเป็น JSON หมด ไม่มี stream)

**ทำไมต้องมีบัฟเฟอร์ 10 วินาที**
`vexLine` ถูกเรียกแทบทุกข้อความ ถ้าเขียน DB ทุกครั้งจะเป็นภาระในเส้นทางร้อน
จึงรวมยอดในหน่วยความจำก่อนแล้วเขียนทีเดียว

**ทำไมตอน flush ต้อง "บวกส่วนต่าง" ไม่ใช่ "ทับทั้งก้อน"**
กันกรณีมีมากกว่าหนึ่งโปรเซสเรียก Gemini พร้อมกัน (web + สคริปต์เฝ้า) แล้วเขียนทับกันจนยอดหาย

**ยอมทิ้งยอดเมื่อไหร่**
ถ้าเขียน DB ไม่ได้ ตัวจดจะเงียบแล้วปล่อยผ่าน — **ห้ามให้การนับโทเค็นทำให้งานหลักพัง** ยอมยอดขาดดีกว่า Vex ตอบไม่ได้

**เก็บย้อนหลังกี่วัน**
60 วัน (ค่า `KEEP_DAYS` ใน `gemini-usage.ts`) เกินนั้นตัดทิ้งอัตโนมัติตอน flush ไม่ให้ค่าใน `Setting` บวมไม่จำกัด
